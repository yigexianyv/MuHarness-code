# MuHarness

MuHarness 是一个本地 AI Agent 工作台，支持对话、任务规划、工具执行和交付物管理。用户在浏览器中提出需求，后端负责调用模型、执行工具并保存任务状态。

项目提供两种执行方式：**普通任务**通过模型与工具循环完成工作；**长任务**通过管理、执行、审计三个角色逐步推进，由审计结论和后端守卫共同决定是否记入完成进度。模型判断仍可能出错，重要结果应结合实际文件和工具证据核对。

## 核心能力

| 能力 | 说明 |
| --- | --- |
| 任务执行 | 文件读写、Shell、HTTP、网页搜索；支持计划确认和运行预算 |
| 长任务协作 | 角色分工、独立审计、中途补充要求、暂停与继续、停滞检测 |
| 上下文与记忆 | 压缩时间线、摘要对比、请求原文、必须记住的事项，以及长期记忆检索 |
| 技能与扩展 | Skills 加载、技能候选生成、MCP 接入与工具按需发现 |
| 权限与隔离 | 工具审批、角色白名单、Docker Shell 沙箱 |
| 记录与交付 | 执行轨迹、工具证据、检查点、文件与链接发布 |
| 自动化 | 定时触发任务，查看执行结果 |

前端包含工作台、自动化、待处理、账本、记忆和设置。审批与任务提问在「待处理」中处理，执行记录、审计结论和交付物在「账本」中查看。

## 执行流程

```text
普通任务：用户需求 → 模型决策 → 工具执行 → 结果反馈 → 最终答复

长任务：确认计划 → 管理者规划 → 执行者执行 → 审计者验收
        通过：保存进度，进入下一步或最终验收
        未通过：反馈证据，重新规划与执行
```

长任务的三个角色共用主模型，分别构建上下文。管理者没有工具；执行者按授权范围操作工作区并发布交付物；审计者通过只读工具检查文件和证据。任务中断后，可核查已有结果并继续。

文件通过 `artifact_publish` 工具发布，由后端保存副本并返回字节数和 SHA-256 摘要，之后修改工作区原文件不会影响已发布副本。

## 继续任务与重新执行

聊天页的「当前任务」面板提供两个明确入口：

| 操作 | 行为 |
| --- | --- |
| 继续剩余阶段 | 直接启动所选任务的长任务执行，保留已完成步骤，推进剩余阶段 |
| 从阶段 1 重新执行 | 创建一份新任务，将有效步骤设为待执行，保留原任务记录、目标、约束和验收标准 |

重做时，尚未结束的旧任务会标记为已取消；已完成或已失败的旧任务保留原状态。旧步骤和运行记录保留，新任务的运行记录从零开始。

两个按钮直接调用执行接口，不依赖模型从“继续”“重做”等文字猜测操作，也不经过 PLAN 消息路径。任务需要有效步骤和验收标准；已有未结束长任务时，应使用长任务面板的继续或取消入口。重做可能覆盖工作区同名文件，不会自动还原文件或外部系统。

PLAN 模式用于调查和保存计划，不执行工作区写入。仅在输入框发送“继续”不会自动切换模式。新计划仍通过计划卡片确认后执行；已完成任务可选择重新执行。

## 上下文透明度

打开「账本 / 成果 → 执行记录 → 某次执行详情」，在「上下文」区域查看：

- **用量与时间线**：每次模型请求的上下文用量、是否压缩、压缩前后估算用量。
- **摘要与原文**：七字段摘要、前后版本差异，以及被摘要替代的消息原文。
- **三层工具输出**：区分工具返回的完整内容、执行器保存的内容和本次请求实际采用的内容；可分别查看完整原文与模型请求视图。
- **约束遗漏提醒**：新摘要中不再出现的旧约束会提示核对。这是文本差异提示，不代表已证明模型遗忘，也可能来自改写。
- **必须记住的事项**：保存会话约定，每次模型请求读取最新版本；运行中修改会从下一次请求生效，面板记录所选步骤采用的版本。

请求视图记录的是发给模型适配器的消息内容，不代表能够观察服务商内部处理。旧运行若没有相应记录，会明确提示不可用。

### 模式支持范围

| 能力 | NORMAL 普通模式 | PLAN 计划模式 | MEA 长任务 |
| --- | --- | --- | --- |
| 原文记录、逐步请求视图、会话约定 | 已接入 | 共用普通会话记录机制 | 尚未完整接入 |
| 上下文管理与执行 Trace | 支持 | 支持 | 支持，各角色独立构建上下文 |
| 执行详情中的「重做此步」 | 支持符合条件的手动运行 | 不支持 | 不支持 |

MEA 的上下文管理和 Trace 不等于完整的透明度面板支持；目前会话中的「必须记住」也不会自动注入各个 MEA 角色。长任务约束应写入任务要求或通过长任务需求修订提交。

## 执行回溯

普通模式的执行详情页包含「执行时间线」。点击「重做此步」，可预览文件变化、填写纠正，并恢复到该次模型请求之前的检查点，生成分支会话。纠正内容预填到新会话输入框，发送后再执行；原会话和执行记录保留。

- 只支持已有检查点的手动 NORMAL 运行，且执行须已结束；其他执行活跃时不能回退。
- 文件回退仅覆盖工作区快照范围；数据库、网络请求、长期记忆等外部效果不会随之撤销。
- 回退前保存备份；分支会话横幅可返回来源或撤销文件回退，具体可用性以预览和校验结果为准。
- 工作区文件数量或总大小超过快照限制时，对应步骤不可回退。

「重做此步」是从中间检查点分叉；「从阶段 1 重新执行」是创建新任务从头执行，两者用途不同。

## 快速开始

需要 **Python 3.13+、Node.js 20+、npm、Docker Engine**，以及一个模型服务商 API Key。Windows 使用 Docker Desktop 时，请启动 Linux 容器引擎。

以下命令使用 PowerShell，所有终端均从仓库根目录开始。

### 1. 构建沙箱

```powershell
docker info
docker build -t muharness-sandbox:latest -f .\backend\docker\sandbox\Dockerfile .\backend
```

Shell 在一次性容器中执行，默认禁网。镜像使用 Python 3.14，包含项目 Python 依赖、Git、Make 和 ripgrep；其他运行依赖可在 Dockerfile 中配置。

### 2. 启动后端

在第一个终端运行：

```powershell
cd .\backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (!(Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
```

在 `backend/.env` 中选择服务商并填写密钥：

| 服务商 | `MODEL_DEFAULT_PROVIDER` | 密钥变量 |
| --- | --- |
| Anthropic | `anthropic` | `ANTHROPIC_API_KEY` |
| OpenAI | `openai` | `OPENAI_API_KEY` |
| 通义千问 | `qwen` | `QWEN_API_KEY` 或 `DASHSCOPE_API_KEY` |
| DeepSeek | `deepseek` | `DEEPSEEK_API_KEY` |

模型名称使用对应的 `*_MODEL` 变量配置。更多配置见 .env.example，也可在工作台「设置」中调整模型。

```powershell
.\.venv\Scripts\python.exe -m app.server --host 127.0.0.1 --port 8000
```

后端健康检查：<http://127.0.0.1:8000/health>。

### 3. 启动前端

在第二个终端运行：

```powershell
cd .\web
npm ci
npm run dev
```

打开 <http://127.0.0.1:5173>，即可提出任务。需要多步骤验收时，先确认计划，再启动长任务。

前端默认连接 `http://127.0.0.1:8000`；其他地址通过 `VITE_AGENT_SERVER_URL` 设置。命令行对话可在 `backend` 目录运行 `.\.venv\Scripts\python.exe -m app`。

## 一个可运行的例子

先使用普通模式验证工具链：

```text
只在 workspace/demo 目录操作，不调用网络工具。
1. 创建 demo/a.txt，内容为 v1，然后读取核验。
2. 将 demo/a.txt 改为 v2，创建 demo/b.txt，内容为 hello。
3. 读取两个文件，报告实际内容。任一步失败最多重试一次，仍失败则停止并说明原因。
```

需要独立验收时，在 PLAN 模式保存相同任务的步骤与验收标准，再从计划卡片启动长任务。可在执行详情查看 Trace 和工具证据；测试“重做此步”时，应使用普通模式运行，并先核对回退预览。

短任务通常适合普通模式。长任务会额外调用管理者和审计者，完成业务步骤后还需要最终验收和结果汇总，因此耗时通常更长。

## 长任务状态与已知限制

| 状态 / 现象 | 含义与处理 |
| --- | --- |
| `running` / `finalizing` | 正在执行、审计或汇总；先查看当前角色和最近工具事件 |
| 等待审批 | 工具尚未得到授权，在待处理入口决定是否批准 |
| `paused` | 用户请求暂停或轮次预算耗尽；按提示追加轮次后继续 |
| `waiting_user` | 需要回答问题、补充要求或处理停滞原因 |
| `blocked` | 当前要求或输入使任务无法继续，不代表程序崩溃 |
| `failed` | 运行异常终止，查看具体错误、子运行与 Trace |

- 长任务的暂停通常在本轮结束后生效，并非立即终止当前工具。普通运行中断可能留下效果不确定的调用，恢复前需要核查。
- 已复现的展示问题：轮次预算耗尽后追加预算并完成，记录可能仍保留 `abort_reason=max_rounds`。目前尚未修复；应结合当前状态和最新轮次判断，不能仅凭旧原因认定任务仍停止。
- 审计原文可能出现矛盾判断。例如业务读取失败却写出 `satisfied`；后端会对明确阻断约束执行完成守卫，实际任务状态可能与原始审计文字不同。
- 用户自然语言中的业务重试上限并非所有场景都有独立的程序计数保障。角色/API重试、工具重试和业务重试是不同层次，不能把一次实测通过视为普遍保证。
- 完整上下文透明度与步骤回溯尚未覆盖 MEA。项目面向本地单用户，不承诺多用户并发隔离或外部副作用回滚。

## 项目结构

技术栈：**Python + FastAPI + SQLite**，**React + TypeScript + Vite**。前后端通过 WebSocket JSON-RPC 通信，实时推送模型输出、工具调用、审批和任务状态。

```text
backend/
├── app/
│   ├── runtime/         Agent 循环、长任务、上下文、运行与检查点
│   ├── domain/          会话、任务、自动化、记忆、技能与交付物
│   ├── integrations/    MCP 与扩展接入
│   ├── safety/          审批与沙箱
│   ├── records/         执行轨迹与工具证据
│   ├── models/          模型适配与命令行入口
│   ├── model_settings/  模型配置
│   ├── tools/           工具注册、执行器与权限
│   ├── server/          HTTP 与 JSON-RPC 服务
│   └── application.py   应用装配
├── tests/               回归测试与评测
└── docker/sandbox/      沙箱镜像
web/src/                 页面、组件、RPC 客户端与状态管理
workspace/               Agent 工作区
```

## 数据与使用说明

- Agent 工作文件位于 `workspace/`，在 Shell 容器中对应 `/workspace`。
- 运行数据默认保存在 `backend/.muharness/`，包括数据库、任务、记忆、配置和交付物；用户级技能位于主目录下的 `.muharness/skills/`。默认路径不再从其他名称的数据目录回退读取。
- API Key 在后端环境变量或 `backend/.env` 中配置，不应提交到仓库。
- 项目面向本机单用户使用。Shell 由 Docker 隔离，文件工具由后端校验工作区路径；RPC 不提供多用户鉴权。
- Docker 不可用时不会自动回退为本机 Shell 执行。后端源码更新后，需要完整重启后端进程。

## 开发与测试

### 上下文策略

项目使用单一的“首次固定工具视图 → 普通轮次追加 → 达到阈值集中摘要”策略，没有 `legacy|stable` 开关，旧的反复裁剪工具结果和单独删除旧工具轮的实现已删除。

- 原始会话、工具执行记录和证据保持原文；首次给模型的工具结果只缩 JSON 的 `output`，错误、成功状态和证据元数据不变，此后复用固定文本。
- Task 状态按版本追加为后端生成的数据，不提升为系统授权；模式、审批和工具权限仍由执行层控制。真实系统指令或工具定义变化可以重建请求。
- 仅集中阈值触发摘要，可覆盖本轮已完成工具轮；保留当前用户要求、近期尾部及不完整工具配对。摘要水位只统计原始消息，不含临时注入。空摘要、失败或无长度收益均不替换历史。
- 会话终态将原始历史、摘要和工具视图一起事务保存；视图按原始消息序号与 SHA-256 匹配。旧历史缺少记录时保守使用原文，不回溯截断。新表在初始化时自动创建，无需清空数据库。
- 前端分别展示本地追加/重建/压缩与服务商缓存用量；缺统计是未知，不是零命中。终态保存支持继续运行，但不承诺硬崩溃时精确重放未保存轮次，也不保证上游一定命中 KV cache。

`CONTEXT_COMPACT_INPUT_TOKENS` 可指定集中阈值；未设置时默认使用 preferred input 的两倍并受硬窗口限制。工具视图使用现有 `CONTEXT_MAX_TOOL_RESULT_CHARS` 和 head/tail 设置。`read_file` 可通过 `start_line`（从 1 起）和 `max_lines` 限量读取，仅传 `path` 保持原行为。

### 回归命令

在 `backend` 目录运行：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
```

默认回归不调用真实模型 API；真实 Docker 隔离测试通过 `MUHARNESS_RUN_DOCKER_E2E=1` 开启。

行为评测用真实模型跑固定场景（基础行为、上下文压缩、长任务），需要显式执行，会产生模型费用：

```powershell
.\.venv\Scripts\python.exe -m tests.eval list
.\.venv\Scripts\python.exe -m tests.eval run --suite behavior --repeat 3
.\.venv\Scripts\python.exe -m tests.eval ab --variants prompt-v1,current --suite behavior --repeat 3
```

`ab` 让两个变体（例如新旧提示词）跑同一批用例并输出对照表；报告写到 `backend/tests/eval/reports/`。

在 `web` 目录运行：

```powershell
npm test
npm run build
```

构建命令包含 TypeScript 类型检查。
